# COORD_CALLOUT.lsp (VERTEXLEADERS)

AutoLISP-скрипт для AutoCAD, автоматизирующий простановку координатных выносок и линейных размеров по вершинам полилинии — стандартная задача при оформлении геодезических / топографических чертежей.

Скрипт проставляет координаты X/Y по каждой вершине выбранной полилинии (или сразу нескольких), номера вершин, размеры по каждому сегменту (с учётом рядом расположенных М-линий), а также формирует и экспортирует итоговую таблицу координат — без ручного черчения выносок и без ручного набора текста.

## Возможности

- **Координаты по вершинам полилинии** — на выбор один из двух способов вывода:
  - **Мультивыноска (MLEADER)** со строками `X= ...` / `Y= ...`;
  - **Атрибутивный блок «XY»**, вставляемый точкой вставки прямо в вершину — без линии-выноски.
- **Выбор сразу нескольких полилиний за один запуск** — координаты, номера и размеры проставляются по каждой из них, со сквозной нумерацией вершин между ними.
- **Параллельные размеры** по каждому сегменту полилинии, смещённые под линию на заданное расстояние:
  - если сегмент достаточно длинный — значение показывается прямо на линии размера;
  - если сегмент короткий и цифры не помещаются — значение автоматически выносится отдельной мультивыноской в сторону.
- **Учёт М-линий рядом с полилинией.** Если вдоль сегмента полилинии идёт М-линия (MLINE) — обычный размер по этому сегменту не проставляется (чтобы не дублировать почти одинаковое значение), а вместо этого М-линия получает свой размер с подписью `L=` или `L-` (на выбор). Подробнее — см. раздел [«Размеры и М-линии»](#размеры-и-м-линии).
- **Сквозная нумерация вершин** между несколькими полилиниями в рамках одного сеанса — с возможностью продолжить нумерацию или начать заново.
- **Автоматическое обновление координат при перемещении и копировании блока.** Если координата вставлена как атрибутивный блок, его впоследствии переместили (MOVE, растяжение, ручки) или скопировали (COPY) — значения X/Y в атрибутах пересчитываются автоматически, без участия пользователя.
- **Экспорт таблицы координат** по завершении построения — в CSV (для Excel) и/или RTF (для Word).
- **Самодостаточный файл.** Чертёж-шаблон с нужными стилями оформления встроен в сам `.lsp`-файл (в виде base64) и автоматически распаковывается при первой загрузке — никаких дополнительных файлов рядом со скриптом носить не нужно.
- **Автоматический импорт оформления** из встроенного шаблона: стиль мультивыноски «Координаты», текстовый стиль «Д-431», размерный стиль «ISO-500 пустой COORD», блок «XY». Если импорт по какой-то причине не удался — скрипт продолжает работу на базе стиля Standard, назначая всё необходимое оформление вручную, объект за объектом.

## Требования

- AutoCAD (или платформа на его движке, поддерживающая AutoLISP + Visual LISP / ActiveX).
- Права на запись во временную папку пользователя (`%TEMP%`) — туда распаковывается встроенный шаблон стилей при первой загрузке.
- Папка со скриптом должна входить в список «Доверенные расположения» AutoCAD (**ОПЦИИ → Файлы → Доверенные расположения**) — иначе загрузка через APPLOAD завершится ошибкой без подробностей.

## Установка

1. Скачайте файл `COORD_CALLOUT.lsp`.
2. Загрузите его в AutoCAD одним из способов:
   - команда **APPLOAD** (**ЗАГПРИЛ**) → выбрать файл → «Загрузить»;
   - перетащить файл в окно AutoCAD;
   - добавить в автозагрузку через **Диспетчер приложений** (APPLOAD → «Стартовый набор» / Startup Suite), если скрипт нужен постоянно.
3. При успешной загрузке в командной строке появится:

+---------------------------------------------------+
| vertex_leaders.lsp успешно загружен. |
| Доступные команды: |
| VERTEXLEADERS — координаты + размеры + экспорт |
| CHECKSTYLE — проверить/импортировать стили |
| RESETVERTEXNUM — сбросить счётчик нумерации |
+---------------------------------------------------+


> При самой первой загрузке скрипт распаковывает встроенный чертёж-шаблон во временную папку (`%TEMP%\template.dwg`) — это происходит один раз и подтверждается сообщением «Распаковываю встроенный шаблон стилей... Готово.».

## Команды

### `VERTEXLEADERS`

Основная команда. Последовательность работы:

1. Запустите команду и выберите одну или несколько полилиний (`LWPOLYLINE`, `POLYLINE` или `3DPOLYLINE`) — завершите выбор клавишей ENTER.
2. Ответьте на короткую серию вопросов (для каждого — значение по умолчанию в `<>`, достаточно нажать ENTER, чтобы его принять):
   - проставлять ли номера вершин;
   - проставлять ли размеры сторон;
   - если размеры включены — какой префикс использовать для длины М-линий: `L=` или `L-`;
   - способ вывода координат — **Мультивыноска** или **Блок**;
   - если это не первая полилиния в сеансе — продолжить сквозную нумерацию вершин дальше или начать заново с №1.
3. Скрипт автоматически проставит по каждой выбранной полилинии:
   - координатные подписи по каждой вершине;
   - номера вершин (если включено);
   - параллельные размеры по каждому сегменту — либо размер самой полилинии, либо, если рядом идёт М-линия, размер этой М-линии с префиксом `L=`/`L-` (см. ниже);
4. По завершении будет предложено экспортировать итоговую таблицу координат в CSV и/или RTF.

**Пример диалога:**

Команда: VERTEXLEADERS
=== Простановка координатных выносок и размеров по полилинии ===
Выберите нужные полилинии (можно несколько).
Когда все нужные объекты выбраны — нажмите ENTER, чтобы завершить выбор.
Выберите объекты: найдено: 1
Выберите объекты: найдено: 1, всего: 2
Выберите объекты:
Выбрано полилиний: 2
Проставлять номера вершин? [Да/Нет] <Да>:
Проставлять размеры сторон? [Да/Нет] <Да>:
Префикс длины М-линий? [L=/L-] <L=>:
Способ вывода координат? [Мультивыноска/Блок] <Мультивыноска>:
Нумерация вершин начнётся с №1.


### `CHECKSTYLE`

Служебная команда для диагностики — проверяет наличие и при необходимости повторно импортирует текстовый стиль «Д-431» и стиль мультивыноски «Координаты» из встроенного шаблона. Удобна для быстрой проверки оформления без запуска полного цикла построения.

### `RESETVERTEXNUM`

Сбрасывает сквозной счётчик нумерации вершин, накопленные данные для экспорта и карту занятых мест под подписи. Используйте, если нужно начать нумерацию заново «с чистого листа» в рамках текущего сеанса, не перезапуская AutoCAD.

### `REFRESHCOORDBLOCKS`

Служебная команда, связанная с автообновлением координат в атрибутивных блоках (см. раздел ниже). Пере-навешивает системные реакторы на все блоки «XY» в текущем чертеже. **Обязательно выполняйте её один раз после каждого открытия/переоткрытия файла**, содержащего ранее расставленные координатные блоки, — реакторы не сохраняются в самом DWG между сеансами AutoCAD.

## Размеры и М-линии

Если вдоль сегмента полилинии проходит М-линия (например, дорога или коммуникация, нарисованная поверх контура полилинии), скрипт не ставит по этому сегменту обычный размер полилинии — вместо этого измеряется и подписывается сама М-линия:

- подпись строится как `<префикс><длина>`, например `L=24.15` или `L-14.00`, где префикс задаётся в начале команды (`L=` или `L-`);
- размерная линия и подпись всегда ориентированы вдоль самой М-линии (а не по фиксированному направлению), с отступом в сторону от полилинии, чтобы не накладываться на другие подписи;
- если несколько выбранных полилиний оказались рядом с одной и той же М-линией, подпись для неё будет поставлена только один раз за весь запуск команды — повторных дублирующихся `L=`/`L-` не будет;
- на сегментах, где рядом нет М-линии, размер полилинии проставляется как раньше — обычным числом, без префикса.

## Автообновление координат при перемещении и копировании блока

При использовании способа вывода **«Блок»** скрипт навешивает на каждый вставленный блок системный реактор AutoCAD. Как только блок перемещают (перетаскиванием, командой MOVE, растяжением) — значения атрибутов X/Y пересчитываются автоматически и мгновенно, сразу после завершения соответствующей команды редактирования.

Это работает и для **копий** блока: после копирования (COPY) новый экземпляр блока автоматически обнаруживается по завершении команды, на него сразу навешивается тот же реактор, а его атрибуты X/Y пересчитываются по фактическому положению копии — вручную ничего донастраивать не требуется.

Важно понимать одно ограничение: реакторы существуют только в оперативной памяти текущего сеанса AutoCAD и не сохраняются вместе с файлом чертежа. Поэтому при каждом новом открытии чертежа, где уже есть расставленные координатные блоки, нужно один раз выполнить команду `REFRESHCOORDBLOCKS`, чтобы механизм автообновления (в том числе для будущих копий) снова заработал.

## Настройка

Ключевые параметры оформления заданы в начале тела команды `VERTEXLEADERS` и могут быть изменены под конкретный проект:

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `mleader-style-name` | Имя стиля мультивыноски | `Координаты` |
| `text-style-name` | Имя текстового стиля | `Д-431` |
| `dim-style-name` | Имя размерного стиля | `ISO-500 пустой COORD` |
| `coord-block-name` | Имя блока для режима «Блок» | `XY` |
| `block-scale` | Масштаб вставки блока (только геометрия, высота текста атрибутов не зависит от него) | `1.0` |
| `txt-height` | Высота текста координат/номеров | `1.0` |
| `dim-offset` | Смещение линии размера полилинии от самой полилинии | `1.0` |
| `dim-text-gap` | Отступ текста от линии размера | `0.5` |
| `parallel-search-dist` | Радиус поиска соседних выбранных полилиний (для выбора стороны размера) | `10.0` |

Отдельные внутренние параметры простановки размеров М-линий (радиус поиска М-линии рядом с полилинией, отступ подписи `L=`/`L-` от самой М-линии) заданы внутри функций `vl:mline-near-segment-p` и `vl:dim-mlines-near-polyline`.

## Известные ограничения

- Реакторы автообновления координат (в том числе для копий блока) сбрасываются при закрытии чертежа/AutoCAD — требуется `REFRESHCOORDBLOCKS` после каждого открытия файла (см. выше).
- Импорт стилей из шаблона выполняется через временную вставку всего шаблонного DWG как блока с последующим удалением экземпляра; определение блока-шаблона при этом остаётся в таблице блоков чертежа — это ожидаемое и безвредное поведение.
- Размер по сегменту полилинии пропускается, если рядом найдена достаточно близкая и параллельная сегменту М-линия. В редких случаях сложной геометрии (острые углы, М-линии, идущие почти вдоль соседнего, а не «своего» сегмента) это определение может сработать не так, как ожидалось — стоит визуально проверить результат перед сдачей чертежа.
